The Grid's Own Language

AI assistants for power-system operators compute with validated solvers, yet still read the network through names. The industry already has a language that says what every element is. What happens when the assistant reads it?

Antonio Alcántara, Ioannis Karampinis and Spyros Chatzivasileiadis · CUNEF Universidad and DTU

Read the full paper CONDUCTOR on GitHub github.com/antonioalcantaramata/CONDUCTOR

Assistants built on large language models (LLMs) are entering power-system operation. An operator asks in plain language for a security assessment, a contingency screen or a corrective dispatch, and the assistant sets up the study, runs it and explains the result.

The prevailing design keeps the LLM away from the arithmetic: every number comes from a validated power-system solver. That makes the numbers right. But a correct number is only half of an answer. The other half is what the number is about.

1Which units are solar?

Here is a small test. Below are the fifteen generating and storage units of a benchmark distribution grid, the way an assistant usually meets them: by name. Ask it the question an operator might ask before a cloudy afternoon.

“Solar Farm North” is a diesel combined heat and power unit. “PV Park East” is a fuel cell. Both facts are in the data, in a type field of the tool's own tables, but the assistant never read that field. It read the names.

This is not a contrived failure. Names are weak evidence even within a single utility, and an assistant that counts a diesel unit among the solar units, or takes a normally open tie to be in service, fails at the first step of situational awareness: perceiving the elements of the system. Every study built on that perception inherits the error. A study that “halves the solar output” will cut the diesel unit too.

2The industry already has a language

Utilities describe their networks in the Common Information Model (CIM), an IEC standard. European system operators exchange their grid models in it, following the Common Grid Model Exchange Standard (CGMES). CIM defines what each element is, what properties it has, and how it relates to the others, so that any two tools that read CIM understand a network the same way.

These are exactly the facts an assistant needs, and exactly the ones it gets wrong without them. But CIM leaves one thing out. It does not record how each fact is known: whether it is stated in the data, only suggested by a name, or inferred.

A unit's type field is evidence. Its name is not.

3A CIM layer for the assistant

The paper proposes a CIM layer: a description of the network in CIM, built from the network's own data, that both the assistant and the studies it runs read. It is implemented in CONDUCTOR, an open-source assistant for grid monitoring and corrective decision support. The layer describes each element through facts, such as “PV 9 is solar”, of three types:

(i) Attributes that are in the data, but in fields of each tool's own tables that the agent never reads: a unit's energy source, a switch's normal state, a bus's voltage.
(ii) Relations that no table stores, derived from the topology: what an outage disconnects, which feeder supplies a load, which normally open switch ties two feeders.
(iii) Provenance: how each fact is known.

stated
in the data, such as a unit's type field
named
only the element's name suggests it
inferred
derived from the topology
declared
added by the operator, such as “unit 12 is a wind farm”
unknown
the network does not say, and the assistant must not guess

Numerical values carry their origin too: a load's reactive power is either measured or derived from an assumed power factor. The layer is read in three ways: the agent queries it, the studies query it, and the answer checks compare every answer with it.

4Explore the network

Below is the CIGRE medium-voltage benchmark used in the paper: a 110/20 kV substation feeding two radial feeders, with 15 buses, 18 loads, eight PV units, a wind turbine, a diesel CHP unit, fuel cells, two batteries, and three normally open switches. Everything in the figure is drawn from the layer's facts.

Tap any bus, line, unit or switch to see what the layer says about it, and how each fact is known. Then trip a line: the layer works out, from the topology alone, which buses lose supply and which normally open tie could restore them. This calculation runs live in your browser.

Try the paper's two scenarios. Trip Line 2–3: buses 3 to 11 lose supply (11 loads, 4.3 MW nominal), and the layer finds that the normally open tie S1 on Line 14–8 could restore them. Because that is inferred from the topology without a power flow, the answer warns that closing S1 is not a verified switching plan.

Then halve wind and solar. With the layer, the study changes exactly the eight PV units and the wind turbine. Turn the layer off and the study cannot tell what a unit is, so it cuts every generating unit, the diesel CHP unit and the fuel cells included. With the layer on, tap Fuel cell 1 at bus 9 and declare it a wind turbine: the same study now changes 10 units. Without the layer, the declaration changes nothing.

5Checking every answer

Before an answer reaches the operator, three checks compare it with what is known. They are fixed rules, not a second AI model, and what they flag is shown below the answer.

Numbers are matched against the solver results, the study parameters and the question, at the precision they are written. Statements about elements are compared with the CIM layer: a statement the layer contradicts is a failure; one it does not support, a warning. Earlier assistants could check only the numbers. With the layer, the checks also verify what the answer says about the network. Conclusions are re-run under the readings the question left open.

Plant an error in the answer below and see which check catches it. Beside it is how often that kind of error was caught when the authors planted it in the 2,717 answers recorded in their experiments.

6What the layer adds

The authors wrote 88 tasks, each with grading criteria the agent never sees, checked automatically against the network or the study's own record, never by a model. 37 of them ask about the network. Each was run 5 times in three variants, with the same LLM and the same instructions: the full system, the layer hidden from the agent but still read by the studies, and no layer at all. A further experiment let the agent read the network's raw data tables instead of the layer.

The agent misses exactly the facts it cannot see. It trusts names, so it counts the diesel unit as solar. It cannot name the normally open switches or the tie between the feeders, nor tell a measured value from one derived from a power factor, so it declines or guesses. Raw tables fix the names, because they hold the attributes, but they hold neither relations nor provenance. In no run did the agent reading raw tables name the feeder that supplies a load, or the tie that restores supply after an outage.

The agent does not reason better; it reasons from better facts.

A second experiment ran all 88 tasks three times in eight variants (2,112 runs), each removing one part of CONDUCTOR. “Solvers only” is an agent with every solver tool but no layer and no re-run, the way earlier assistants are built.

7Why not paste the tables in?

If raw tables already hold the attributes, why not hand them to the LLM? Because they do not scale. Written out as text, they take about 200 tokens, some 800 characters, per bus. Drag the slider from a benchmark feeder to a transmission system.

8The grid's own language

AI grid assistants compute with solvers but still read the network through names. CIM tells them what each element is; the CIM layer adds how each fact is known. With it, the agent met at least 97 % of the grading criteria on questions about the network, against 84 % with raw data tables and at most 65 % without it. Re-running the studies under the parameters a question left open changed one conclusion in five. And because operators already keep their networks in CIM, the layer loads their CGMES models directly.

The study has limits the authors spell out: the networks are benchmarks with synthetic data, chosen because their facts are known; real models bring incomplete data; and every run used one LLM. The next steps are other LLMs, system operators' own models, and studies with control-room operators on whether CIM-based answers improve their situational awareness and trust.

Grid assistants should read the grid's CIM by default.
